The development of HTTP

Each major change addressed a limitation in the web that came before it.

The early web and HTTP/0.9

Tim Berners-Lee developed the web at CERN around 1989–1991. HTTP supplied a way to retrieve linked documents, alongside HTML, an early browser, and server software. Its initial setting was much smaller than today's public web.

The early protocol later called HTTP/0.9 used a simple GET line followed by a document response. It lacked the status line and header fields that later versions use to explain what came back.

That simplicity made an initial document exchange possible, but it gave software little information about errors or different content types. A larger web needed a more expressive message format.

            Illustrative HTTP/0.9 request:
GET /welcome.html

The response contains the document itself,
without a modern status line or header section.

Read more: MDN: Evolution of HTTP, W3C: The early HTTP protocol.

HTTP/1.0 and richer representations

RFC 1945 documented HTTP/1.0 in May 1996. Its authors were Tim Berners-Lee, Roy Fielding, and Henrik Frystyk Nielsen. The document described existing practice rather than presenting HTTP/1.0 as an Internet Standard.

Version information, response status codes, and header fields made exchanges easier to interpret. Content-Type allowed the response to identify formats beyond HTML, supporting the growing variety of resources used by web pages.

The basic connection model still carried a cost. A connection generally served one request and response, so loading a page with several resources involved repeated setup. Later work addressed that overhead while preserving the richer messages.

            HTTP/1.0 200 OK
Content-Type: image/png

[image data]

The header identifies the representation's media type.

Read more: RFC 1945: HTTP/1.0.

HTTP/1.1 and reusable connections

The first HTTP/1.1 specification, RFC 2068, appeared in January 1997. It developed a more explicit standard for a web that was already using multiple resource types and many server implementations.

Persistent connections let several exchanges reuse a connection. The Host field identified the requested host, which helped servers distinguish sites sharing an address. Chunked transfer coding supported message bodies whose final length was not known at the start.

These changes made the protocol more suitable for larger pages. Reusing a connection reduced repeated work, although it did not remove every delay created by the order of requests and responses.

Read more: RFC 2068: HTTP/1.1 (1997), RFC 9112: HTTP/1.1.

Milestones at a glance

Publication milestones and their significance
Period Development Why it matters
1989–1991 Early web and HTTP/0.9 Linked documents could be retrieved through a simple request.
May 1996 HTTP/1.0, RFC 1945 Status codes and fields documented richer exchanges.
January 1997 HTTP/1.1, RFC 2068 Reusable connections reduced repeated setup.
2015 Original HTTP/2 standard Multiplexing changed how responses share a connection.
June 2022 HTTP/3, RFC 9114 QUIC supplied a different transport for HTTP.
