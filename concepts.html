Seven key concepts

Short definitions, with examples drawn from an ordinary website.

These definitions provide a reference for the rest of the site. I find the examples useful because the terms describe specific parts of an exchange that are easy to confuse when a page fails to load.

Client and server

A client initiates a request, and a server responds to it. A browser commonly acts as the client. The roles describe an exchange, rather than two permanent categories of computer.

Example: A browser requesting index.html acts as the client.

Resource

A resource is the target identified by a URI. Its representation is the information transferred about it, such as an HTML document or JSON data. A resource and one returned file are not always the same thing.

Example: An article address can identify a resource whose current representation is HTML.

Request and response

A request describes what the client wants to do. A response communicates the result with a status and relevant fields, plus content when appropriate. One visible page may depend on several of these exchanges.

Example: The HTML document and its stylesheet can arrive through separate requests.

Method

A method gives a request its intended action. GET requests a representation, while POST asks the target resource to process supplied content. Choosing a method does not itself encrypt the exchange.

Example: GET /lesson.html requests a lesson representation.

Status code

A status code communicates the result in a form software can recognize. A successful retrieval commonly returns 200, while 404 indicates that a current target representation was not found.

Example: A wrong image path may return 404 even when the main page loads.

Cache

A cache stores a response for possible reuse under HTTP caching rules. Freshness and validation determine when a stored copy can satisfy another request. Reuse can reduce both waiting and network traffic.

Example: A stored stylesheet may be reused while it remains fresh.

Multiplexing

Multiplexing allows several logical streams to share a connection. HTTP/2 interleaves frames on TCP, while HTTP/3 maps exchanges onto QUIC streams. The transport beneath the streams affects how missing data causes delay.

Example: A stylesheet stream and an image stream can share an HTTP/2 connection.

Read more: RFC 9110: HTTP Semantics, MDN: Request methods, MDN: Status codes, RFC 9111: HTTP Caching, RFC 9113: HTTP/2, RFC 9114: HTTP/3.
